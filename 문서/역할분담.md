# 2인 개발 역할 분담 및 공통 규칙

구현 수치·행동·화면·데이터 형식은 [개발가이드.md](개발가이드.md)를 따른다. 이 문서에서는 누가 어떤 파일과 기능을 맡는지 확인한다.

## 1. 두 사람이 함께 완성할 범위

첫 프로젝트는 **Processing Java Mode 기반의 2D 한국 숲 생태계**다. 풀과 동물 6종이 상호작용하는 시뮬레이션부터 지도 조작, 개체 정보, 개체 수 그래프, 먹이 피라미드, 실험 설정, 가뭄과 산불까지 포함한다. 개발은 **생태 규칙 → 관찰 화면 → 사용자 조작과 재해** 순으로 진행한다. 바다와 도시는 숲 버전 이후의 확장 대상이다.

| 담당 | 책임 범위 |
|---|---|
| **A · 생태 시뮬레이션** | 동물과 풀의 상태를 계산한다. 이동, 먹이 탐색, 사냥, 번식, 사망을 구현하고 화면에 필요한 데이터를 제공한다. |
| **B · 화면·조작·통계·재해 진행** | 지도와 동물을 그린다. 마우스와 버튼 조작, 개체 정보, 그래프, 두 피라미드를 만들고 재해의 발생과 화면 표시를 담당한다. |

## 2. A의 상세 작업 · 생태 시뮬레이션

| 작업 | 구현할 내용 |
|---|---|
| **시간과 초기화** | 화면 그리기와 별도로 일정한 시뮬레이션 단계마다 숲을 갱신한다. 일시정지·재개·배속·초기화 요청을 실제 시뮬레이션에 적용한다. 새 실행마다 동물과 풀을 무작위로 배치한다. |
| **초기 개체와 종별 능력치** | 개발 가이드의 종별 시작 수량을 적용하고, 각 종의 암수를 절반씩 배치한다. 이동속도·시야·체력·수명 등은 종별 설정으로 관리한다. |
| **탐색과 이동** | 격자로 가까운 후보를 찾고 거리와 전방 시야각을 확인한다. 평상시에는 조금씩 무작위로 회전하며 이동한다. 동물이 칸을 옮기거나 죽고, 풀이 먹히거나 다시 생길 때 격자 목록을 갱신한다. |
| **추격과 도망** | 포식자는 사냥감을 쫓고, 놓치면 마지막으로 본 위치로 향한다. 초식동물은 포식자를 발견하면 도망치고 탈진하면 전력 질주를 멈춘다. 포식자는 탈진하는 즉시 추격과 공격을 중단한 뒤 휴식 조건을 확인한다. 재추격 조건은 개발 가이드 기준을 적용한다. |
| **먹이와 사냥** | 삵은 대륙밭쥐·멧토끼를, 담비는 대륙밭쥐·노루·고라니를 사냥한다. 두 포식자는 사냥감을 일정 시간 발견하지 못하고 에너지도 낮을 때 풀을 찾는다. 풀에서 얻는 에너지는 초식동물보다 적다. 공격 피해를 누적하고 사냥에 성공한 포식자에게 에너지를 한 번 지급한다. 먹힌 풀은 일정 시간 뒤 무작위 위치에 다시 생성한다. |
| **포만과 회복** | 에너지·지구력·체력을 따로 관리한다. 배가 부르면 이동속도와 움직이는 빈도가 줄어든다. 멈춰 쉬면 지구력이 회복되고, 에너지가 충분하면 체력도 회복된다. |
| **번식과 사망** | 같은 종의 성체 암수가 거리·에너지·대기 시간 조건을 충족하면 번식한다. 새끼의 성별은 각각 50% 확률로 정한다. 포식·굶주림으로 체력이 0이 되거나 개별 수명에 도달하면 사망 처리한다. |
| **설정과 재해 적용** | 시작 전 선택한 삵·담비 수와 번식 간격 설정을 적용한다. 시뮬레이션 시간에 맞춰 B가 만든 재해 판정기를 호출한다. 가뭄 중에는 풀 재생을 늦추고, 산불 구역의 풀과 동물에 피해를 적용한다. |

**주요 담당 클래스** — `Simulation`, `EcosystemConfig`, `SpeciesProfile`, `Animal`, `Plant`, `SpatialGrid`

## 3. B의 상세 작업 · 화면·조작·통계·재해 진행

| 작업 | 구현할 내용 |
|---|---|
| **배경·사물 에셋** | 잔디 바닥·나무·바위·강·호수의 이미지를 선택하고 잘라 화면에 배치한다. 먹이용 풀은 A가 제공한 위치와 존재 상태에 따라 표시한다. 에셋의 출처와 라이선스를 보관한다. |
| **지도와 카메라** | 풀과 동물을 그린다. 개발 가이드의 지도 크기와 배율을 적용하고 드래그 이동과 휠 확대·축소를 연결한다. |
| **동물 선택과 정보 표시** | 클릭 위치를 지도 좌표로 변환해 동물을 선택한다. 선택한 동물의 능력치와 현재 행동을 보여준다. 지도를 보면서 오른쪽 패널의 그래프·피라미드·개체 정보 탭을 전환할 수 있게 한다. |
| **종별 개체 수 그래프** | A가 전달한 시작 개체 수와 출생·사망 시점을 기록한다. 여섯 종을 구분하고, 멸종한 종의 그래프는 0마리로 이어서 표시한다. |
| **두 피라미드** | 오른쪽 탭의 상세 피라미드는 풀·초식동물·포식자 합계에 비례해 층의 폭을 그린다. 지도 왼쪽 상단의 작은 피라미드는 세 층의 합계를 항상 보여준다. 두 화면은 A가 전달한 같은 수량을 사용한다. |
| **진행 버튼과 실험 설정** | 시작·일시정지·재개·초기화와 세 가지 배속 버튼을 만든다. 초기화 후에는 시작 대기를 표시한다. 시작 전에 삵·담비 수를 각각 짝수로 조절할 수 있게 하고, 번식 간격 입력을 연결한다. |
| **재해 판정과 표시** | 진행 중인 재해가 없으면 시뮬레이션 속 하루에 한 번 `없음 / 가뭄 / 산불`을 확률로 판정한다. 발생하면 종류별 범위 안에서 지속 시간을 정한다. 재해 상태와 산불 구역을 표시하고, 같은 구역 정보를 A에 전달한다. |

**주요 담당 클래스** — Processing 스케치, `SimulationView`, `Camera2D`, `PopulationHistory`, `DisasterController`

## 4. 연결 작업의 담당

- **A**는 완료된 시뮬레이션 상태와 출생·사망 사건을 제공한다. 초기화와 새 실행의 시작 기록도 관리한다.
- **B**는 지도·그래프·피라미드에 상태와 사건을 반영하고, 조작 요청과 재해 판정 결과를 연결한다.
- **함께 확인** — 필드·단위·호출 시점과 첫 병합 예시는 [개발 가이드](개발가이드.md) 6절을 따른다.

배경 배치는 B가 담당하고, 지형의 위치와 지도 단위는 A와 함께 맞춘다. 강·호수의 통행 제한이나 생태 효과를 합의하면 A가 시뮬레이션 규칙으로 적용한다.

## 5. 병합 순서와 검증 담당

| 단계 | A가 준비할 것 | B가 준비할 것 | 함께 확인할 것 |
|---|---|---|---|
| **1. 생태 규칙** | 기본 72마리로 동물과 풀이 자동으로 움직이고 상호작용하는 실행본 | 예시 데이터로 만든 지도·그래프·피라미드 화면 | A가 제공할 개체·통계 데이터를 B의 화면에서 읽을 수 있는지 확인 |
| **2. 관찰 화면** | 실제 출생·사망 기록과 현재 합계 | 실제 데이터가 연결된 그래프와 두 피라미드 | 출생·사망 직후 세 화면의 수량이 일치하고, 멸종한 종은 그래프에 0마리로 남는지 확인 |
| **3. 조작과 재해** | 설정 적용, 초기화, 가뭄·산불 효과 | 카메라·개체 선택·버튼·탭, 재해 판정과 표시 | 확대 후 개체 선택, 일시정지·재개·초기화, 재해 구역 일치, 1배속·3배속 동작 확인 |
| **4. 성능과 균형 검증** | 개체 수가 늘어날 때 격자 탐색과 상태 갱신에 걸리는 시간을 측정 | 조작 반응과 그래프 표시를 확인하고, 조건별 개체 수와 멸종 시점을 정리 | 기본 조건과 초기 포식자 수·번식 간격·풀 공급을 바꾼 조건을 비교하고 조정할 값을 합의 |

## 6. 공통 작업 규칙

1. **개발 가이드를 구현 기준으로 사용한다.** 수치나 동작을 바꾸려면 두 사람이 합의하고 개발 가이드의 해당 항목을 먼저 갱신한다. 영향을 받는 기능 설명이나 테스트도 함께 확인한다.
2. **숲의 상태는 `Simulation`에서 관리한다.** 화면은 완료된 단계의 상태를 읽어 표시하고, 버튼과 마우스 입력은 조작 요청으로 전달한다.
3. **시간과 좌표 단위를 공유한다.** 수명·번식·재해는 시뮬레이션 시간을 사용한다. 지도 좌표와 동물 방향은 개발 가이드의 데이터 단위를 따른다.
4. **공통 파일의 작업자를 정한다.** 같은 파일이나 전달 데이터의 형식을 바꿀 때는 작업 전에 상대방에게 변경 내용을 알리고 담당자 한 명을 정한다.
5. **feature → dev → main 순서로 병합한다.** 최신 dev에서 기능 브랜치를 만들고 상대방의 확인 후 dev에 통합한다. dev의 통합 테스트를 통과한 결과를 main에 병합한다. 작업을 넘길 때 바뀐 기능·확인 방법·남은 문제와 테스트 결과를 기록한다.

공통 데이터 형식은 SharedTypes.pde에서 함께 합의하고 A가 편집한다. 메인 스케치는 B가 편집하되 A와 호출 순서를 맞춘다. A는 생태 계산에 지도 단위를 사용하고, B는 화면 표시와 클릭 좌표 변환을 담당한다.

## 7. 개발 브랜치와 병합 절차

기능 개발은 최신 dev에서 만든 작업 브랜치에서 진행합니다. 각 기능을 dev에 통합한 뒤 테스트를 통과한 결과를 main에 병합합니다.

| 브랜치 | 역할 |
|---|---|
| main | 통합 테스트를 통과한 실행 가능한 버전 |
| dev | A와 B의 기능을 모아 연결하고 테스트하는 통합 브랜치 |
| feature/기능명 | dev에서 분기해 개별 기능을 개발하는 브랜치 |

1. main을 기준으로 dev를 만들고 팀원이 함께 사용합니다.
2. 각자 최신 dev에서 feature/animal-movement, feature/map-view 같은 기능 브랜치를 만듭니다.
3. 담당 기능을 구현하고 빌드·기능 검증을 한 뒤 feature 브랜치에서 dev로 Pull Request를 엽니다.
4. 상대방이 변경 내용을 확인하면 dev에 병합합니다. 충돌을 해결한 경우 통합된 코드로 다시 확인합니다.
5. dev에서 이번에 통합한 기능과 영향을 받는 기존 기능을 함께 테스트합니다. 실패하면 dev에서 분기한 수정 브랜치로 해결하고 다시 통합·검증합니다.
6. 통과 기준을 충족하면 dev에서 main으로 Pull Request를 열어 함께 확인한 뒤 병합합니다. 테스트 이후 dev에 변경이 추가됐다면 최신 병합 대상에 대해 다시 검증합니다.

main 병합 전에는 Processing 빌드와 실행, 통합한 기능의 동작, A와 B의 데이터 연결을 확인합니다. 해당 기능이 구현된 단계부터 개체 수와 그래프·피라미드의 일치, 지도 조작, 일시정지·배속·초기화, 재해를 검증합니다. 세부 시나리오는 [개발 가이드](개발가이드.md)의 테스트 계획을 따르고 확인한 결과를 Pull Request에 기록합니다.
