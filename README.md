# Forest Ecosystem

Processing Java Mode로 만드는 **2D 한국 숲 생태계 시뮬레이션**입니다.

동물들이 이동하고 먹이를 탐색하며, 사냥·번식·사망하는 과정을 구현합니다. 시간에 따른 개체 수 변화와 환경 조건이 생태계에 미치는 영향을 관찰하는 대학 기말 프로젝트입니다.

## 주요 기능

- 멧토끼·대륙밭쥐·노루·고라니·삵·담비의 자율 행동
- 풀 섭취와 재생, 추격·도망·사냥
- 에너지·체력·지구력, 번식과 사망
- 종별 개체 수 그래프와 먹이 피라미드
- 지도 이동·확대·축소와 동물 정보 확인
- 가뭄·산불, 초기 포식자 수와 번식 간격 조절
- 일시정지·배속·초기화

## 현재 진행 상태

- 설계 문서와 역할 분담 정리 완료
- Processing 프로젝트 기본 파일 생성 완료
- 초기 프로젝트 뼈대의 기본 스케치 빌드 확인 완료
- B 첫 단계 구현 — 숲·강·호수 배경, 정적 예시 동물 72마리·풀 120개, 지도 조작과 개체 정보
- B 두 번째 단계 구현 — 오른쪽 탭, 종별 개체 수 그래프, 상세·소형 먹이 피라미드
- A의 실제 생태 데이터 연결과 후속 버튼·재해 기능은 다음 단계

## 실행 방법

1. Processing을 설치하고 **Java Mode**를 선택합니다.
2. 저장소를 내려받습니다.
3. `ForestEcosystem/ForestEcosystem.pde`를 엽니다.
4. 실행 버튼을 누릅니다.

현재 실행하면 **정적 예시 데이터**로 숲 지도가 표시됩니다. 동물은 아직 움직이지 않습니다.

- 마우스 왼쪽 드래그로 지도 이동
- 휠로 커서 위치 중심 확대·축소
- 동물을 클릭해 오른쪽에서 능력치와 현재 상태 확인
- R 키로 카메라를 시작 배율과 중심으로 복귀
- 오른쪽 개체 정보·그래프·피라미드 탭을 클릭해 관찰 정보 전환
- 왼쪽 상단 작은 피라미드에서 현재 풀·초식동물·포식자 합계 확인
- 정적 예시에서는 시간과 개체 수가 고정되어 그래프의 초기점이 표시됨

현재 단계는 사용자 요청에 따라 자동 테스트와 빌드·실행 검증을 생략했습니다. dev와 main의 병합은 각각 진행 전에 사용자에게 묻고 명시적인 승인을 받은 뒤 수행합니다.

## 역할 분담

| 담당 | 주요 작업 |
|---|---|
| A | 시간 진행, 동물·풀 상태, 탐색·사냥·번식·사망, 재해 효과 적용 |
| B | 배경·사물 이미지 준비와 지도 배치, 카메라·조작, 개체 정보, 그래프·피라미드, 재해 판정과 표시 |

공유 데이터 형식과 프로그램 연결은 두 사람이 함께 맞춥니다.

배경의 잔디·나무·바위·강·호수는 B가 에셋을 골라 자르고 화면에 배치합니다. 먹이용 풀의 위치·섭취·재생은 A가 관리하고, B가 그 상태에 맞춰 표시합니다. 강과 호수의 위치 데이터는 함께 맞추고, 물을 건널 수 있는지 같은 행동 규칙을 합의하면 A가 적용합니다.

## 개발 브랜치와 병합 절차

기능 개발은 최신 dev에서 만든 작업 브랜치에서 진행합니다. 각 기능을 dev에 통합한 뒤 테스트를 통과한 결과를 main에 병합합니다.

| 브랜치 | 역할 |
|---|---|
| main | 통합 테스트를 통과한 실행 가능한 버전 |
| dev | A와 B의 기능을 모아 연결하고 테스트하는 통합 브랜치 |
| feature/기능명 | dev에서 분기해 개별 기능을 개발하는 브랜치 |

**기능별 작업은 사용자 승인 후 dev에 통합합니다. main은 모든 기능을 팀원과 함께 통합 확인한 뒤, 사용자의 최종 병합 요청을 받아 반영합니다. 기능 완료나 테스트 통과만으로 병합하지 않습니다.**

1. main을 기준으로 dev를 만들고 팀원이 함께 사용합니다.
2. 각자 최신 dev에서 feature/animal-movement, feature/map-view 같은 기능 브랜치를 만듭니다.
3. 담당 기능을 구현하고 빌드·기능 검증을 한 뒤 feature 브랜치에서 dev로 Pull Request를 엽니다.
4. 상대방이 변경 내용을 확인하면 dev에 병합합니다. 충돌을 해결한 경우 통합된 코드로 다시 확인합니다.
5. dev에서 이번에 통합한 기능과 영향을 받는 기존 기능을 함께 테스트합니다. 실패하면 dev에서 분기한 수정 브랜치로 해결하고 다시 통합·검증합니다.
6. 통과 기준을 충족하면 dev에서 main으로 Pull Request를 열어 함께 확인한 뒤 병합합니다. 테스트 이후 dev에 변경이 추가됐다면 최신 병합 대상에 대해 다시 검증합니다.

main 병합 전에는 Processing 빌드와 실행, 통합한 기능의 동작, A와 B의 데이터 연결을 확인합니다. 해당 기능이 구현된 단계부터 개체 수와 그래프·피라미드의 일치, 지도 조작, 일시정지·배속·초기화, 재해를 검증합니다. 세부 시나리오는 [개발 가이드](문서/개발가이드.md)의 테스트 계획을 따르고 확인한 결과를 Pull Request에 기록합니다.
